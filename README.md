# MyWaveDiscordBot

- Авторизация через Яндекс Музыку
- Воспроизведение персонализированной станции "Моя волна"
- Настройки волны, как в приложении: занятие, характер, настроение и язык
- История воспроизведения: к недавним трекам можно вернуться
- Автоматическое воспроизведение следующих треков
- Отображение информации о текущем треке

## Настройка приложения в Discord

Привилегированные интенты (Message Content, Server Members, Presence) боту не нужны.
При приглашении бота выберите scopes `bot` и `applications.commands` и права: «Просмотр каналов», «Отправка сообщений», «Встраивать ссылки», «Подключаться» и «Говорить».

## Установка

1. Клонируйте репозиторий:

   ```
   git clone https://github.com/Crosbic/MyWaveDiscordBot.git
   cd MyWaveDiscordBot
   ```

2. Установите зависимости:

   ```
   yarn install
   ```

3. Создайте файл `.env` на основе `.env.template`:

   ```
   cp .env.template .env
   ```

4. Заполните файл `.env` необходимыми данными:

   ```
   # Токен Discord бота
   DISCORD_TOKEN=ваш_токен

   # ID клиента (приложения)
   CLIENT_ID=ваш_id

   # Ключ шифрования токенов Яндекса в базе: openssl rand -hex 32
   # Не меняйте его после запуска, иначе сохранённые токены не расшифруются
   ENCRYPTION_KEY=ваш_секретный_ключ

   # Список Discord ID (рекомендуется) или username администраторов бота, через запятую
   ADMINS=ваш_discord_id
   ```

5. Запустите бота в режиме разработки:

   ```
   yarn dev
   ```

   Слеш-команды регистрировать вручную не нужно: при каждом запуске бот сверяет их с Discord и обновляет, если они изменились.

## Запуск в Docker

Образ собирается из ветки `master` и публикуется в GitHub Container Registry.

База с токенами пользователей хранится в `/app/data/data.db`, токены в ней зашифрованы ключом `ENCRYPTION_KEY`. При каждом обновлении контейнер создаётся заново, поэтому каталог `/app/data` обязательно подключите как постоянное хранилище, иначе после каждого деплоя всем придётся авторизоваться заново. При старте бот пишет в лог путь к базе и число пользователей, а если база создана заново, предупреждает об этом.

Если в каталоге лежит `users.db` от старых версий бота, при старте пользователи и настройки серверов из неё переносятся в `data.db` (из двух записей одного пользователя остаётся более свежая). Старый файл переименовывается в `users.db.migrated-<дата>` и остаётся как резервная копия.

С docker compose (файл `docker-compose.yml` лежит в репозитории, рядом с ним нужен `.env`):

```
docker compose pull
docker compose up -d
```

Или напрямую через docker run:

```
docker run -d --name my-wave --restart unless-stopped \
  --env-file .env \
  -v my-wave-data:/app/data \
  ghcr.io/crosbic/ympb-player-bot:master
```

Оба варианта используют один и тот же volume `my-wave-data`. Если вместо volume подключаете каталог сервера, сделайте его владельцем пользователя с UID 1000: от его имени работает бот. Если платформа даёт постоянное хранилище по другому пути (например, `/data`), укажите этот путь в переменной `DATA_DIR`.

Схема базы версионируется: при обновлении бот сам применяет новые миграции и перед этим сохраняет копию базы рядом с ней (`data.db.backup-v<версия>-<дата>`, хранятся три последние).

Уровень логов задаётся переменной `LOG_LEVEL`: `debug`, `info`, `warn`, `error` или `silent`. По умолчанию `info`, а при `DEBUG=true` — `debug`.

Первой строкой лога бот пишет коммит, из которого собран образ, по нему видно, обновился ли бот после деплоя:

```
Запуск бота: коммит 38c83b7 от 2026-11-10T14:01:39+03:00
```

Коммит и его дату CI передаёт при сборке через `--build-arg`. Если собираете образ вручную, передайте их сами, иначе в логе будет «коммит неизвестен»:

```
docker build --build-arg GIT_COMMIT=$(git rev-parse HEAD) --build-arg GIT_COMMIT_DATE=$(git log -1 --format=%cI) -t ympb-player-bot:master .
```

## Разработка

| Команда             | Что делает                                                                  |
| ------------------- | --------------------------------------------------------------------------- |
| `yarn dev`          | Запуск бота с перезапуском при изменениях                                   |
| `yarn test`         | Тесты; плеер проверяется на настоящем аудиоплеере с тестовыми аудиофайлами  |
| `yarn typecheck`    | Проверка типов, включая тесты                                               |
| `yarn lint`         | ESLint                                                                      |
| `yarn format`       | Prettier                                                                    |
| `yarn api:generate` | Заново сгенерировать типы API Яндекс Музыки из спецификации                 |
| `yarn deploy`       | Зарегистрировать слеш-команды вручную (обычно не нужно, бот делает это сам) |

После `yarn install` включаются git-хуки:

- pre-commit — ESLint и Prettier для файлов в коммите (lint-staged);
- commit-msg — проверка сообщения коммита (commitlint);
- pre-push — сборка и тесты.

Сообщение коммита пишется в формате `тип(область): описание` со строчной буквы и без точки в конце, например `fix(player): повтор трека после обрыва потока`. Типы: `build`, `chore`, `ci`, `docs`, `feat`, `fix`, `perf`, `refactor`, `revert`, `style`, `test`, `translation`, `security`, `changeset`, `tune`, `cleanup`.

CI на каждый push проверяет типы, линтер, форматирование и тесты. Образ Docker собирается и публикуется только из `master` и только после успешных проверок.

## Команды

| Команда                    | Описание                                             |
| -------------------------- | ---------------------------------------------------- |
| `/login`                   | Войти в аккаунт Яндекс Музыки по коду                |
| `/logout`                  | Выход из аккаунта Яндекс                             |
| `/my-wave`                 | Воспроизвести треки из "Моя волна" в Яндекс Музыке   |
| `/account-info`            | Показать информацию о подключенном аккаунте Яндекс   |
| `/allow-buttons <enabled>` | Включить/выключить публичный доступ к кнопкам плеера |
| `/ping`                    | Проверить задержку бота                              |

### Авторизация через Яндекс Музыку

1. Выполните `/login`: бот покажет код
2. Откройте [ya.ru/device](https://ya.ru/device) на телефоне или компьютере, где вы вошли в Яндекс, введите код и разрешите доступ
3. Бот сам заметит вход и сообщит, в какой аккаунт вы вошли

Можно сразу выполнить `/my-wave`: если вы ещё не вошли или вход перестал действовать, бот покажет такой же код, а после входа сам запустит волну.

Код действует 5 минут, новый можно получить кнопкой в том же сообщении. В Яндекс ID вход будет подписан как «Discord-бот My Wave», там его можно и отключить. Токен Яндекса живёт год, и при запуске волны бот продлевает его, если до конца срока осталось меньше девяти месяцев (Яндекс советует продлевать токены раз в три месяца). Поэтому, если запускать волну хотя бы раз в девять месяцев, входить заново не придётся. `/logout` удаляет токен у бота и отзывает его в Яндексе.

Если вход по коду не подходит, нажмите «Ввести токен вручную» и вставьте токен Яндекс Музыки, полученный [любым из способов](https://ym.marshal.dev/token). Можно вставить и всю ссылку, в которой есть `access_token=`. Такой токен бот не продлевает и при выходе не отзывает: он может работать и в других приложениях. Когда он истечёт, войдите заново.

### Воспроизведение музыки

1. Подключитесь к голосовому каналу
2. Используйте команду `/my-wave` для начала воспроизведения вашей персонализированной станции
3. Бот автоматически будет воспроизводить следующие треки

Волна настраивается кнопками в плеере. «⚙️ Настроить волну» открывает панель, которую видите только вы: занятие, характер, настроение и язык. Новые настройки применяются сразу: начинает играть первый трек новой волны, а «По умолчанию» возвращает волну без настроек. Пока у волны есть настройки, в плеере видна кнопка «↩️ Сбросить настройки». Бот запоминает настройки отдельно для каждого пользователя и запускает с ними его следующий `/my-wave`. Если поменять настройки в чужом плеере, они запомнятся за вами, а не за владельцем плеера. Нажимать эти кнопки могут те же пользователи, что и остальные кнопки плеера.

Кнопка «🎡 Подборки» в плеере показывает подборки из карусели Яндекс Музыки, подобранные под то, что сейчас играет: например, волны по жанру, настроению или артисту. Выбранная подборка сразу начинает играть. Характер, настроение и язык из «⚙️ Настроить волну» добавляются к подборке, а занятие её заменяет. Подборка запоминается так же, как настройки, кроме «Встряхнуть Мою волну»: это разовое действие.

Кнопка «📜 История» показывает последние 25 сыгранных треков по пять на странице, сверху — последний. Историю видите только вы. Кнопка ▶️ у трека сразу его включает: прерванный трек уходит в историю, как после ⏭️, а после выбранного волна продолжается. Нажимать эти кнопки могут те же пользователи, что и остальные кнопки плеера.

Повторный `/my-wave` от того же пользователя перезапускает плеер. Пока плеер занят другим пользователем, запустить свою волну на этом сервере нельзя.

Бот сам выходит из голосового канала, если:

- в канале 20 секунд нет слушателей;
- пауза длится дольше 10 минут;
- музыка не играет 30 секунд.

### Настройка публичного доступа к управлению плеером

По умолчанию только пользователь, запустивший воспроизведение, может управлять плеером (нажимать кнопки паузы, следующего трека и т.д.). Кнопку 👍 может нажать любой: трек добавится в «Мне нравится» его собственного аккаунта. Администраторы сервера могут включить публичный доступ к кнопкам плеера (настройка сохраняется после перезапуска бота):

1. Используйте команду `/allow-buttons true` для включения публичного доступа
2. Используйте команду `/allow-buttons false` для выключения публичного доступа

Доступ к этой команде имеют:

- Администраторы сервера
- Пользователи, указанные в параметре `ADMINS` в файле `.env`

**Важно**: Если публичный доступ включен, пользователи должны находиться в том же голосовом канале, что и бот, чтобы иметь возможность управлять плеером. Администраторы сервера и пользователи из списка `ADMINS` могут управлять плеером из любого канала.

## Примечания

- Для использования бота требуется активная подписка Яндекс Плюс
- Вход по коду не истечёт, если запускать волну хотя бы раз в девять месяцев: бот продлевает его сам. Токен, вставленный вручную, бот не продлевает
- Бот может воспроизводить музыку только в голосовых каналах, к которым у него есть доступ
